# 典型方法

- 树的问题，基本上逃不掉遍历，代码都会有前中后序，或是层次的影子，且递归是这些遍历的较为简单的实现，往这里靠，思路会好像很多
- 长指针判断，cur->left->left也是可行的，只要逻辑理清，边界（如上层指针不空再下层，可以用&&短路配合）处理得当，就没问题，不用执着于奇技淫巧
- 算法题可以多用点全局变量
- 构造一棵树肯定优先考虑前序，中左右，有了中就可以划分左右，而其他的不行。
- 以2个遍历序列构造二叉树，必须有一个中序，用于区分左右，前序后序左右都是挨在一块没法分割。
- 一些复杂度，尽管逻辑相似遍历，但也不一定就是按节点计算，也有可能是按层计算，即每一层处理共0(n)，一共 h 层，总复杂度=n*h
- 有的时候可以牺牲内存，也就是故意内存泄漏，换取稳定性与通过率
- BST与中序遍历强相关，而且大部分存数组的算法可以等价替换为，仅用pre指针的算法，思路一样，逻辑一样，但性能后者更好，这是一定要想到的

## leetcode_617_merge_two_binary_trees

### 先科普下指针传值需要注意的点

```cpp
void f(TreeNode* p) {   // p 是外部那个指针的【副本】，两个变量，值相同
    p = nullptr;        // (A) 改【指针变量本身】
    delete p;           // (B) 销毁【指针指向的那块内存】
    p->val = 1;         // (C) 改【对象的内容】
}
```

(A) 改一级指针变量，必须二级指针（或指针引用）才能同步到外部。其余都可同步

### 当前写法存在问题

#### 问题 1：tree2 的所有权被劈成两半

同一个树里，重叠节点被删除、非重叠节点被接管。这是最难推理的一种所有权模型——你必须记住"哪些死了、哪些活着"才能安全使用 root2。

#### 问题 2：root2 悬垂，调用方一碰就是二次释放

顶层帧执行了 delete t2，而 t2 就是 main 的 root2。所以函数返回后 root2 是悬垂指针。

此时 main 只调了 deleteTree(root1)，没碰 root2，所以本文件不崩。但如果谁写了 deleteTree(root2)，会发生：

节点 2、1、3 → 二次释放（第 35 行已经 delete 过了）
节点 4、7 → 二次释放（已被 deleteTree(root1) 释放过）
全崩。第 57–58 行那段注释警告的就是这件事，它是对的、且必须保留。

#### 问题 3：delete t2 时，t2->left / t2->right 已经是悬垂的

按顺序看第 33–35 行：

leetcode_617_merge_two_binary_trees.cppL33-L35
t1->left = InOrder(t1->left, t2->left);
t1->right = InOrder(t1->right, t2->right);
delete t2;
以 tree2 的节点 1 为例：它的 right 是节点 4，节点 4 走的是"复用"分支被 t1 接管了；它的 left… 再看节点 2：递归进 (3,1) 那一支时，节点 1 已经在子帧里被 delete 了，所以此时 节点2->left 是悬垂的。接着第 35 行 delete 节点 2。

---

为什么现在没炸？ 只因为 tree_node.h 里的 TreeNode 是平凡结构体、没有析构函数，delete 不会去碰它的 left/right 字段。

一旦有人给 TreeNode 加上：

```cpp
~TreeNode() { delete left; delete right; }
```

delete t2 就会去 delete t2->left —— 而这个节点刚被删过，或者已经被 t1 接管进了结果树。立刻变成重复释放 / 结果树悬垂。这是与头文件的隐式强耦合，从这份代码里完全看不出来。

#### 问题 4：t2 = nullptr 是纯无效代码

如第一节所述，它只改了形参副本。删掉不损失任何功能。

#### 问题 5：t1 == t2 时 UAF（边界）

若 mergeTrees(root1, root1)，则 t1 == t2：t1->val += t2->val 把值翻倍，最后 delete t2 把 t1 也删了，返回的 ret 直接悬垂。LeetCode 不会这么调。

### 解决方案

#### 方案 A（最省事，推荐）：删掉第 36 行 t2 = nullptr;，然后在 main 里手动置空外部变量——这是唯一能真正"同步"的地方：

```cpp
printTree(solution.mergeTrees(root1, root2));
root2 = nullptr;   // merge 内部已 delete 掉重叠节点，外部指针作废，防止误用
deleteTree(root1);
```

#### 方案 B：把 delete t2; t2 = nullptr; 两行都删掉。

好处：root2 不再悬垂。
代价：tree2 的重叠节点泄漏（本地 demo 无所谓，OJ 进程结束回收）。
注意：共享问题依然存在，deleteTree(root2) 照样会让 4、7 二次释放，注释还得留着。
方案 C：什么都不改，保持现状 + 保留第 57–58 行注释。

完全可用，能过 OJ。
代价：root2 悬垂、delete t2 依赖 TreeNode 无析构，这两颗雷埋着。
